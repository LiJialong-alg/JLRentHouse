## 1. 引言

### 1.1 背景

随着城市化进程的加快和人口流动性的增加，公寓租赁市场需求日益旺盛。传统的公寓租赁管理方式主要依靠人工记录和纸质文档，存在效率低下、信息查找困难、数据容易丢失等问题。为了提高公寓租赁管理的效率和质量，开发一套功能完善、操作简便的公寓租赁管理系统具有重要的现实意义。

### 1.2 目的

本文档的目的是详细描述公寓租赁管理系统的功能需求和非功能需求，为后续的设计、开发和测试提供明确的需求依据。本文档是项目各方对系统需求的一致理解，是项目开发的基础和验收的标准。

### 1.3 范围

本系统面向两类用户：
- **管理员用户**：公寓租赁企业的运营人员，负责公寓信息管理、预约处理、租约管理等业务操作
- **租客用户**：通过移动端浏览公寓、预约看房的潜在租客

### 1.4 定义与缩写

| 术语/缩写 | 定义 |
|----------|------|
| 公寓 | 整栋或整层楼的租赁房屋 |
| 房间 | 公寓内的单个可租赁单元 |
| 预约 | 租客提交的看房请求 |
| 租约 | 正式的租赁合同 |
| 配套 | 公寓的配套设施（如健身房、停车场等） |
| 标签 | 用于分类和搜索的标识（如"精装修"、"近地铁"等） |

## 2. 总体描述

### 2.1 产品 perspective

公寓租赁管理系统是一套面向公寓租赁企业的信息化管理平台，采用B/S架构，分为管理端（Admin）和用户端（App）。系统提供公寓信息管理、房间管理、看房预约、租约管理、用户管理等核心功能，帮助企业实现租赁业务的数字化管理。

## 3. 功能需求

### 3.1 登录认证模块

#### 3.1.1 管理员登录

| 项目 | 描述 |
|-----|------|
| 功能描述 | 管理员通过用户名和密码登录系统 |
| 前置条件 | 用户已存在于系统中 |
| 基本流程 | 1.用户输入用户名和密码 → 2.系统验证用户信息 → 3.验证成功返回Token → 4.跳转到首页 |
| 异常流程 | 用户名或密码错误，提示"用户名或密码错误" |
| 后置条件 | 用户成功登录系统，获取访问令牌 |

#### 3.1.2 Token认证

| 项目 | 描述 |
|-----|------|
| 功能描述 | 所有API请求需携带有效的Token进行身份认证 |
| 实现方式 | 使用JWT（JSON Web Token）实现无状态认证 |
| Token有效期 | 24小时 |
| 刷新机制 | Token过期后需重新登录 |

#### 3.1.3 退出登录

| 项目 | 描述 |
|-----|------|
| 功能描述 | 用户退出系统，清除本地认证信息 |
| 基本流程 | 1.用户点击退出 → 2.清除本地Token → 3.跳转到登录页 |

| FacilityInfo | 配套设施 | name, icon |
| LabelInfo | 标签 | name, value |

### 4.2 数据完整性要求

1. **必填字段**：关键业务字段不能为空
2. **数据格式**：手机号、身份证号等需符合格式规范
3. **数据一致性**：关联数据需保持一致性（如省市区联动）
4. **数据安全**：敏感数据需加密存储

## 6. 接口规格

### 6.1 统一响应格式

所有API统一返回以下格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| code | Integer | 状态码 |
| message | String | 消息 |
| data | Object | 数据 |

**状态码说明：**
| 状态码 | 说明 |
|-------|------|
| 200 | 成功 |
| -1 | 失败 |
| 305 | Token失效 |
| 601 | 用户不存在 |
| 602 | 密码错误 |

### 6.2 分页响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "records": [],
    "total": 100,
    "size": 10,
    "current": 1
  }
}
```
