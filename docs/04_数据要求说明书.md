## 1. 引言

### 1.1 背景

本文档旨在详细定义公寓租赁管理系统的数据需求，包括数据实体、属性、关系以及数据处理要求。本文档是数据库设计和实现的基础，为开发团队提供明确的数据规范。

### 1.2 范围

本文档涵盖以下数据相关内容：
- 主要数据实体及其属性
- 数据实体之间的关系
- 数据完整性约束
- 数据安全要求
- 数据处理要求

### 1.3 定义

| 术语 | 定义 |
|-----|------|
| 实体 | 客观存在并可相互区别的事物 |
| 属性 | 实体具有的特征 |
| 关系 | 实体之间的联系 |
| 主键 | 唯一标识实体的属性 |
| 外键 | 引用其他表主键的字段 |

### 3.4 预约与租约

#### 3.4.1 预约看房 (ViewAppointment)

| 属性名 | 数据类型 | 长度 | 约束 | 说明 |
|-------|---------|------|------|------|
| id | BIGINT | - | PK | 预约ID |
| name | VARCHAR | 50 | NOT NULL | 预约人姓名 |
| phone | VARCHAR | 20 | NOT NULL | 预约人手机号 |
| appointment_time | DATETIME | - | NOT NULL | 预约看房时间 |
| apartment_id | BIGINT | - | FK | 预约公寓ID |
| additional_info | VARCHAR | 500 | - | 备注信息 |
| appointment_status | TINYINT | - | NOT NULL, DEFAULT 1 | 预约状态：1-待看房，2-已取消，3-已看房，4-已过期 |
| create_time | DATETIME | - | - | 创建时间 |
| update_time | DATETIME | - | - | 更新时间 |

**状态流转：**
```
[待看房] ──取消──> [已取消]
   │
   └──带看完成──> [已看房]
   │
   └──超时──> [已过期]
```

|-------|---------|------|------|------|
| id | BIGINT | - | PK | 租约ID |
| phone | VARCHAR | 20 | NOT NULL | 承租人手机号 |

| apartment_id | BIGINT | - | FK | 签约公寓ID |
| room_id | BIGINT | - | FK | 签约房间ID |
| lease_start_date | DATE | - | NOT NULL | 租约开始日期 |
| lease_end_date | DATE | - | NOT NULL | 租约结束日期 |
| lease_term_id | BIGINT | - | FK | 租期ID |
| rent | DECIMAL | 10,2 | NOT NULL | 租金（元/月） |
| deposit | DECIMAL | 10,2 | - | 押金（元） |
| payment_type_id | BIGINT | - | FK | 支付方式ID |
| status | TINYINT | - | NOT NULL, DEFAULT 1 | 租约状态 |
| source_type | TINYINT | - | NOT NULL | 来源类型：1-新签，2-续约 |
| additional_info | VARCHAR | 500 | - | 备注信息 |
| create_time | DATETIME | - | - | 创建时间 |
| update_time | DATETIME | - | - | 更新时间 |

**状态流转：**
```
[签约待确认] ──确认──> [已签约]
      │
      └──取消──> [已取消]

[已签约] ──到期──> [已到期]
      │
      └──退租确认──> [退租待确认] ──确认──> [已退租]
      │
      └──续约申请──> [续约待确认] ──确认──> [已签约]（新租期）

[已到期] ──续约──> [续约待确认]
```

## 5. 数据完整性约束

### 5.1 主键约束

每个表必须有一个主键（Primary Key），用于唯一标识表中每条记录。

### 5.2 外键约束

| 外键 | 引用表 | 引用字段 | 级联操作 |
|-----|-------|---------|---------|
| city_info.province_id | province_info | id | ON DELETE CASCADE |
| district_info.city_id | city_info | id | ON DELETE CASCADE |
| apartment_info.district_id | district_info | id | ON DELETE CASCADE |
| apartment_info.province_id | province_info | id | ON DELETE CASCADE |
| apartment_info.city_id | city_info | id | ON DELETE CASCADE |
| room_info.apartment_id | apartment_info | id | ON DELETE CASCADE |
| view_appointment.apartment_id | apartment_info | id | ON DELETE CASCADE |
| lease_agreement.apartment_id | apartment_info | id | ON DELETE CASCADE |
| lease_agreement.room_id | room_info | id | ON DELETE CASCADE |

### 5.3 唯一约束

| 字段 | 表名 | 说明 |
|-----|------|------|
| username | system_user | 用户名唯一 |
| phone | user_info | 手机号唯一 |

| 字段 | 表名 | 说明 |

## 6. 数据安全要求

### 6.1 敏感数据加密

| 字段 | 表名 | 加密方式 |
|-----|------|---------|
| password | system_user | BCrypt加密 |
| identification_number | lease_agreement | AES加密存储 |

### 6.2 数据访问控制

- 不同角色只能访问授权范围内的数据
- 敏感操作需记录操作日志
- 定期审计数据访问记录

### 6.3 数据备份策略

| 备份类型 | 频率 | 保存期限 |
|---------|------|---------|
| 全量备份 | 每周一次 | 保留3个月 |
| 增量备份 | 每日一次 | 保留7天 |
| 事务日志备份 | 每小时一次 | 保留24小时 |

## 7. 数据处理要求

### 7.1 数据录入要求

1. 所有必填字段必须填写
2. 手机号需格式验证
3. 日期格式统一为：yyyy-MM-dd
4. 时间格式统一为：yyyy-MM-dd HH:mm:ss
5. 金额保留两位小数

### 7.2 数据查询要求

1. 分页查询默认每页10条记录
2. 支持按省份、城市、区县三级联动查询
3. 支持按名称模糊搜索
4. 支持按发布时间排序

### 7.3 数据删除要求

1. 删除操作需谨慎，重要数据需软删除
2. 删除前需检查是否有下级关联数据
3. 删除操作需记录操作日志
